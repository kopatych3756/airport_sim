Сетевая имитация диспетчерской службы аэропорта на C для Linux. Сервер держит часы модели, очередь и состояние полос. Самолёты, полосы, наблюдатели и клиент управления запускаются отдельными процессами и взаимодействуют по TCP.

## Сборка и быстрый запуск

Нужны компилятор C11 и CMake ≥ 3.16 либо GNU Make. Python 3 нужен для демонстрационного сценария и тестов.

```sh
cmake -S . -B build
cmake --build build -j4
# Либо GNU Make
make -j4 all

# Один процесс на каждую полосу и самолёт и один наблюдатель
python3 scripts/demo_tcp.py
# Короткий сценарий с четырьмя самолётами
python3 scripts/demo_tcp.py -c configs/test_nominal.conf --delay-ms 180
```

Демонстрационный скрипт показывает поток наблюдателя в терминале. В `build/tcp-demo/` остаются журналы отдельных участников и общий `audit.log`. Ctrl+C направляется серверу, который завершает подключённые программы.

## Ручной запуск

В первом терминале запустите сервер в режиме с длительной регистрацией и заметной паузой между тактами:

```sh
./build/airport_server --bind 127.0.0.1 --port 9000 \
    -c configs/test_nominal.conf --startup-ms 120000 --delay-ms 1000 --no-log
```

Во втором терминале зарегистрируйте участников. Строки `ACK READY` и `ACK REQUEST` подтверждают готовность к началу:

```sh
./build/airport_runway 127.0.0.1 9000 R-LONG &
./build/airport_runway 127.0.0.1 9000 R-SHORT &
./build/airport_aircraft 127.0.0.1 9000 A001 &
./build/airport_aircraft 127.0.0.1 9000 D001 &
./build/airport_aircraft 127.0.0.1 9000 A002 &
./build/airport_aircraft 127.0.0.1 9000 D002 &
wait
```

В третьем и четвёртом терминалах запустите по наблюдателю. Затем в свободном терминале запустите смену:

```sh
./build/airport_watch 127.0.0.1 9000 tower
./build/airport_watch 127.0.0.1 9000 apron
./build/airport_ctl 127.0.0.1 9000 start
```

Уровень 4–5 проверяется без наблюдателей. ATC показывает выдачу разрешений, самолёты выводят свои события, полосы выводят события на своей полосе. Один наблюдатель показывает целиком состояние и события аэропорта. Несколько наблюдателей могут подключаться в любой момент. Ctrl+C в терминале наблюдателя отключает только его. Повторный запуск с тем же именем получает снимок на текущем такте.

Для запуска на нескольких Linux-компьютерах соберите программы на каждом из них. На компьютере с сервером задайте его интерфейс или `--bind 0.0.0.0`. В командах удалённых клиентов укажите IP компьютера с сервером и тот же порт, например `192.168.1.20 9000`. Порт должен быть доступен в учебной сети. Программы допускают IPv6, например `::1`. Порт `0` на сервере выбирает свободный порт, который выводится в строке `READY`.

## Управление подключениями

| Команда после `airport_ctl IP PORT` | Результат |
|---|---|
| `status` | Снимок, имена участников, видимость и готовность подключений |
| `start` | Запуск смены до истечения окна регистрации |
| `off RUNWAY R1` | Завершает сессию клиента R1 и запрещает новые подключения этого имени |
| `on RUNWAY R1` | Разрешает запустить клиент R1 повторно |
| `off AIRCRAFT A1`, `on AIRCRAFT A1` | Управляет подключением самолёта |
| `off WATCH apron`, `on WATCH apron` | Управляет подключением наблюдателя |

Для демонстрации используйте `configs/test_tcp_reconnect.conf` с клиентами `R1`, `D1`, `D2`, `A1`. После `D1 started TAKEOFF` выполните `off RUNWAY R1`. D1 закончит взлёт, D2 будет ждать. После `on RUNWAY R1` заново запустите `airport_runway IP PORT R1`. После `ACK READY` и истечения интервала безопасности D2 получит полосу. Возвращённый самолёт получает `ACK REQUEST ALREADY_ACCEPTED`, если сервер уже принял его заявку.

Команды управления по умолчанию доступны через loopback. Для удалённого управления задайте одинаковую переменную `AIRPORT_CONTROL_TOKEN` перед запуском сервера и контроллера. Токен передаётся по TCP открытым текстом. Для демонстрации используйте закрытую учебную сеть.

## Правила запуска и завершения

- Конфигурация из ДЗ 3 задаёт полосы, типы, потоки, интервалы, расход и приоритеты. `airport_ctl status` показывает фактические имена, включая сгенерированные `GA001` и `GD001`.
- Сервер принимает подключения за `--startup-ms` миллисекунд до первых действий модели. Значение по умолчанию 3000. Регистрация доступна и после начала смены. Сервер обрабатывает заявку самолёта начиная с заданного такта после сетевого `REQUEST`. У самолёта без принятого запроса состояние `PENDING`. Для нового назначения требуется подключённая полоса с `ACK READY`.
- Отключение полосы прекращает новые назначения на неё. Начатая операция заканчивается по модельным часам. Заявка самолёта после принятия сохраняется, поэтому отключение клиента не замораживает топливо. Повторная регистрация не создаёт вторую заявку.
- `--seed N`, `--max-ticks N` и `--delay-ms N` переопределяют конфигурацию. Нулевая длина смены отключает её предельный такт. Вывод сервера можно сократить через `--quiet`. `--log FILE` сохраняет общий журнал, `--no-log` отключает его. По умолчанию журнал называется `tcp_simulation.log`.
- Смена заканчивается после обработки заявок, по лимиту тактов либо по SIGINT/SIGTERM серверу. Наблюдатель получает итоговую статистику и незавершённые заявки. Все подключённые клиенты получают `BYE причина` и закрывают сокеты. Сервер возвращает 0 при штатной остановке или окончании смены, 2 при неверных параметрах, 3 при сетевой ошибке или нарушении модели, 4 при ошибке записи журнала и 130 при остановке сигналом.
