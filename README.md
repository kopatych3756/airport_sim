Программа на C для Linux. Самолёты, полосы и диспетчер — отдельные процессы.

## Сборка и запуск

Нужны GCC и CMake >= 3.16. На Windows запускайте команды в Ubuntu/WSL.

```sh
cmake -S . -B build
cmake --build build -j4
./build/airport_named
```

## Четыре версии по критериям задания

| Программа | Процессы | Данные | Семафоры |
|---|---|---|---|
| airport_named | создаются через fork | общая память POSIX | именованные |
| airport_unnamed | создаются через fork | общая память POSIX | неименованные, pshared=1 |
| airport_shm --external | запускаются отдельно | общая память POSIX | именованные |
| airport_fifo --external | запускаются отдельно | каналы FIFO | именованные |

Четвёртая версия использует разрешённый в условии вариант «каналы». Все уровни требований сохранены. Очередей сообщений и настройки их лимитов в упрощённой версии нет.

Для удобного запуска независимых процессов:

```sh
python3 scripts/run_independent.py --mode shm --log logs/shm.log
python3 scripts/run_independent.py --mode fifo --log logs/fifo.log
```

Python нужен только этому скрипту и тестам. Моделирование целиком написано на C.
Скрипт запускает координатор и участников как соседние процессы. Координатор с --external не вызывает fork.

Можно запустить участников вручную. Для test_nominal.conf нужны четыре самолёта, две полосы и диспетчер:

```sh
# Терминал 1
./build/airport_shm --external --session manual -c configs/test_nominal.conf
# Дождаться READY. Затем в другом терминале:
./build/airport --worker shm manual 0 &
./build/airport --worker shm manual 1 &
./build/airport --worker shm manual 2 &
./build/airport --worker shm manual 3 &
./build/airport --worker shm manual 4 &
./build/airport --worker shm manual 5 &
./build/airport --worker shm manual 6 &
wait
```

Для каналов замените airport_shm на airport_fifo, а --worker shm на --worker fifo.
ID 0–3 — самолёты, 4–5 — полосы, 6 — диспетчер. Для другой конфигурации диапазоны ID выводятся в READY. На подключение всех участников отводится 20 секунд. Один ID нельзя подключить дважды.

Без --external версии shm/fifo также умеют сами создавать процессы. Для демонстрации верхних уровней задания используйте независимый запуск.

## Как устроена модель

Все данные находятся в одной структуре Airport. В трёх версиях процессы обращаются к ней прямо в общей памяти. В FIFO-версии координатор передаёт её участнику обычными read/write и получает обратно. Никаких отдельных структур Snapshot и функций упаковки состояния нет.

У каждого участника семафор начала работы. Координатор будит одного участника и ждёт подтверждение. Поэтому одновременно данные меняет только один процесс.

Один такт: самолёты подают запросы и обновляют топливо → полосы завершают операции и обрабатывают закрытия → диспетчер назначает полосы → полосы начинают операции. Затем проверяются инварианты и увеличивается время. Реальное выполнение шагов последовательное; операции на разных полосах могут перекрываться в модельном времени.

Приоритет: аварийный → HIGH/NORMAL/LOW → ранний запрос → порядок во входных данных. Выбирается самая короткая совместимая свободная полоса. Закрытие не прерывает начатую операцию. Топливо означает расходуемый резерв ожидания; ноль приводит к явно записанному DIVERT.

## Настройки

Основные строки:

```text
SEED 31
MAX_TICKS 120
DELAY_MS 0
EMERGENCY_FUEL_TICKS 3
PRIORITY_WEIGHTS 10 65 25
ARRIVAL_FUEL 9 22
ARRIVAL_BURN 1 2
RUNWAY RWY-A 3400 2
TYPE A320 1800 3 3
CLOSE RWY-A 28 38
FLOW ARRIVAL 16 0 1 4
AIRCRAFT A001 ARRIVAL 0 A320 20 1 NORMAL
```

RUNWAY: имя, длина, интервал безопасности. TYPE: имя, нужная длина, время посадки, время взлёта. CLOSE: полоса, начало включительно, конец исключительно. FLOW: операция, число самолётов, первый такт, минимальный и максимальный интервал. AIRCRAFT: номер, операция, такт запроса, тип, топливо, расход, приоритет. Операции: ARRIVAL и DEPARTURE. Приоритеты: LOW, NORMAL, HIGH.

Имена уникальны, до 31 символа. Числа 0..1000000. RUNWAY и TYPE должны быть объявлены до ссылок на них. При одном seed и одной libc генерация воспроизводима.

## Параметры и завершение

-c / --config FILE, --seed N, --max-ticks N, --delay-ms N, --log FILE,
--no-log, --quiet, --help. Универсальная программа airport также принимает
--mode named|unnamed|shm|fifo, --session NAME и --external.
Имя сессии: латинские буквы, цифры, подчёркивание, до 40 символов.

Программа завершается после обработки всех заявок, окончания смены или сигнала. MAX_TICKS=0 отключает ограничение смены. Несовместимый вылет остаётся ждать до конца смены либо Ctrl+C. При завершении выводятся состояния незаконченных заявок.

Ctrl+C останавливает координатор, который завершает остальных. SIGTERM направляйте координатору. После завершения удаляются семафоры, общая память и FIFO. В FIFO-версии общая память не создаётся; каналы находятся в /tmp/airport_UID_SESSION_request и ..._reply.

Коды выхода: 0 — штатно, 2 — неверные данные, 3 — ошибка IPC/инвариантов, 4 — ошибка записи, 130 — остановка сигналом.

SIGKILL и отключение питания не позволяют выполнить очистку. Для остатков своей уже остановленной сессии: python3 scripts/cleanup_session.py SESSION. Не применяйте к работающему запуску.

## Проверка

```sh
sh scripts/run_tests.sh
# Либо после сборки:
ctest --test-dir build --output-on-failure
```

Проверки запускают реальные Linux-процессы: предметные сценарии, независимый запуск, SIGINT/SIGTERM, групповой Ctrl+C, гибель участника, отсутствие оставшихся ресурсов и совпадение событий между версиями. Результаты — report/test_results.txt.
