# Вариант 31 — управление взлётно-посадочными полосами

Учебная последовательная имитационная программа на C для Linux.

Код разбит на несколько небольших файлов, чтобы его было проще читать и защищать. Архитектура намеренно простая: обычные структуры, массивы, функции и один последовательный цикл моделирования.

## Что моделируется

- несколько ВПП разной длины;
- запросы на посадку и взлёт;
- категории приоритета LOW / NORMAL / HIGH;
- аварийный приоритет при малом остатке топлива;
- расход топлива у прибывающих самолётов в очереди;
- интервал безопасности после освобождения ВПП;
- плановые закрытия ВПП;
- уход на запасной аэродром при исчерпании топлива;
- завершение по обработке всех заявок, окончанию смены или Ctrl+C.

Диспетчер представлен отдельной структурой `Dispatcher`. Он хранит своё имя и статистику назначений, а его поведение реализовано функцией диспетчеризации.

При добавлении самолёта программа отдельно проверяет уникальность его номера. Повторяющийся номер считается ошибкой конфигурации и программа не запускает моделирование.

В журнал выводятся REQUEST, QUEUE, FUEL, ASSIGN, START, FINISH, RELEASE, EMERGENCY, DIVERT, CLOSE, OPEN, а также события завершения COMPLETE, SHIFT-END и STOP.

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

## Обычный запуск

```bash
./build/airport_sim --config configs/default.conf --log logs/run.log
```

Наглядный запуск с небольшой задержкой:

```bash
./scripts/run_demo.sh
```

## Параметры командной строки

```text
-c, --config FILE   файл конфигурации
--seed N            переопределить seed
--max-ticks N       длина смены, 0 = без ограничения
--delay-ms N        задержка между тактами
--log FILE          файл журнала
--no-log            не сохранять журнал
--quiet             не печатать события в терминал
-h, --help          справка
```

## Формат конфигурации

Пример:

```text
SEED 31
MAX_TICKS 120
DELAY_MS 0
EMERGENCY_FUEL_TICKS 3
PRIORITY_WEIGHTS 10 65 25
ARRIVAL_FUEL 9 22
ARRIVAL_BURN 1 2

RUNWAY RWY-A 3400 2
TYPE A320 1800 3 3
CLOSE RWY-A 28 38
FLOW ARRIVAL 10 0 1 4
FLOW DEPARTURE 8 0 1 5
```

Для полностью заданного самолёта используется строка:

```text
AIRCRAFT A001 ARRIVAL 0 A320 10 1 NORMAL
```

Номер каждого самолёта должен быть уникальным. Например, две строки с номером `A001` приведут к сообщению `Duplicate aircraft number: A001` и завершению с кодом ошибки.

## Проверка

```bash
./scripts/run_tests.sh
```

Скрипт:

- собирает проект;
- запускает 6 CTest-проверок;
- проверяет основные события через `grep`;
- отдельно проверяет запрет дублирующихся номеров;
- запускает unlimited-сценарий и проверяет корректное завершение по SIGINT с событием STOP и кодом 130.

## Где искать основную логику

Для защиты достаточно понимать четыре файла:

- `main.c` — запускает программу и разбирает аргументы;
- `config.c` — читает исходные данные и создаёт самолёты;
- `simulation.c` — выполняет модель по тактам;
- `io.c` — печатает события в терминал и лог.

Самая важная функция — `run_simulation()` в `simulation.c`. В ней последовательно выполняются завершение старых операций, обработка закрытий, появление новых заявок, аварийные приоритеты, работа диспетчера, расход топлива и проверка инвариантов.
