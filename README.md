# ДЗ №2. Вариант 31: управление взлётно-посадочными полосами

Программа на C для Linux. Каждый самолёт, каждая полоса и диспетчер работают в отдельных потоках pthread. Самолёты запрашивают посадку или взлёт, диспетчер выбирает подходящую полосу. У ожидающих посадки расходуется топливо. Учитываются приоритеты, закрытия и интервалы безопасности.

## Сборка и запуск

Нужны Linux, компилятор C и CMake. Выполнять из корня проекта:

```bash
cmake -S . -B build
cmake --build build
./build/airport_sem --config configs/default.conf --delay-ms 100
./build/airport_cond --config configs/default.conf --delay-ms 100
```

`airport_sem` использует мьютексы и семафоры. `airport_cond` использует мьютексы и условные переменные. Обе программы нужны для основного и дополнительного пунктов ДЗ. Исходники общие; отличается только ветвь в sync.c, выбранная при сборке.

Программа пишет события в терминал и в simulation.log. Для прерывания нажмите Ctrl+C. Для проверки проекта:

```bash
bash scripts/run_tests.sh
```

Тесты сами собирают обе программы и проверяют 16 запусков. Python для сборки и тестирования не нужен. Полученные журналы появятся в logs/tests; их можно удалить после просмотра.

## Аргументы

`--config FILE` (или `-c`) задаёт сценарий, `--seed N` - seed, `--max-ticks N` - последний такт смены (0 означает без лимита), `--delay-ms N` - паузу между тактами. Значение 0 включает быстрый режим с паузой 1 мс.

`--log FILE` задаёт файл журнала, `--no-log` отключает журнал, `--quiet` отключает терминальный вывод, `--help` показывает справку. Числа находятся в диапазоне 0..1000000. Параметры командной строки переопределяют файл.

## Сценарий

```text
SEED 31
MAX_TICKS 100
DELAY_MS 100
EMERGENCY_FUEL_TICKS 3
RUNWAY R1 3000 2
TYPE A320 1800 3 3
CLOSE R1 10 15
AIRCRAFT A001 ARRIVAL 0 A320 10 1 NORMAL
FLOW DEPARTURE 5 0 1 4
```

| Команда | Параметры |
| --- | --- |
| RUNWAY | имя, длина, интервал безопасности |
| TYPE | имя, требуемая длина, длительность посадки, длительность взлёта |
| CLOSE | полоса, начало закрытия, конец закрытия |
| AIRCRAFT | номер, ARRIVAL/DEPARTURE, такт заявки, тип, топливо, расход, LOW/NORMAL/HIGH |
| FLOW | ARRIVAL/DEPARTURE, число самолётов, первый такт, минимум и максимум интервала |
| PRIORITY_WEIGHTS | веса LOW, NORMAL, HIGH для генерации |
| ARRIVAL_FUEL | минимальный и максимальный запас при генерации |
| ARRIVAL_BURN | минимальный и максимальный расход при генерации |

Сначала объявляются полосы и типы, затем ссылки на них. Комментарий начинается с #. Номера самолётов уникальны. Длины, длительности и расход прибывающих положительны; начало закрытия меньше конца. До 300 самолётов, 10 полос, 20 типов, 30 закрытий и 20 FLOW. Имена до 31 байта.

## Что важно понимать для защиты

Состояния самолёта: PENDING → WAITING → ASSIGNED → RUNNING → DONE. Из ожидания возможен DIVERTED. ASSIGNED означает только резерв: перед START поток полосы проверяет закрытие и топливо ещё раз.

Приоритет: аварийный → HIGH/NORMAL/LOW → более ранняя заявка → индекс записи. Выбор среди уже зарегистрированных заявок. Полоса должна быть свободной, открытой, достаточной длины; safety отсчитывается от фактического завершения предыдущей операции. Закрытие не прерывает начатую операцию.

world защищает общие данные. Семафор или условная переменная будит поток, когда появились изменения. Во время ожидания world освобождён. pending сохраняет уведомление до его обработки. При остановке программа выставляет флаг, будит всех, делает pthread_join, затем уничтожает примитивы.

Seed повторяет исходные заявки в одной реализации libc, но порядок событий зависит от планировщика потоков. Топливо - учебный бюджет ожидания: при его нуле фиксируется уход на запасной, сам перелёт не моделируется. Несовместимый вылетающий самолёт ждёт конца смены или сигнала.

Коды завершения: 0 - штатно, 2 - ошибка входа/открытия журнала, 3 - ошибка потоков/состояния или защитный предел времени, 4 - ошибка записи, 130 - SIGINT/SIGTERM. Итог содержит число посадок, взлётов, уходов, ожидающих и незавершённых самолётов.
